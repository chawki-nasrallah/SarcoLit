# `v0.3-eval` — evaluation harness + measured baseline

**Date:** 2026-07-07

## Scope

An automated, reusable evaluation harness for the RAG system, plus the first
**measured baseline** for both stages (retrieval and generation). Turns the
qualitative v0.2 observations into numbers and establishes the reference point
every later tag reports a delta against. Metrics are implemented in-repo (no
heavy eval library). Only the eval *tooling* (question generation + judging)
uses an API model; the RAG system under test stays fully local.

## Architecture

```
RETRIEVAL eval:  query set ──► Retriever.search ──► ranked PMIDs ──► recall@k / MRR / nDCG
                                                     (vs relevant PMIDs)

GENERATION eval: query ──► RagPipeline.ask ──► answer + sources ──► Claude (Opus) judges
                          (local bge+qdrant+Qwen)                    faithfulness
```

## Key decisions

### Ground truth: hybrid — synthetic now, gold deferred to v0.4

- **Synthetic known-item set (delivered).** For each of 150 deterministically
  sampled abstracts (seed 0), Claude (Opus) wrote one realistic question the
  abstract answers; that abstract's PMID is the known-relevant target. Gives
  scale automatically. Frozen + committed (`evals/synthetic_queries.jsonl`).
- **Gold expert set (deferred to v0.4).** A hand-labelled set of realistic
  queries was scoped and tooled (`eval/label_gold.py`, `gold_queries_seed.jsonl`)
  but deferred because pooling candidates from a **single** retriever (bge only)
  causes **self-pooling bias** — relevant docs bge missed never enter the pool,
  so recall is optimistic. v0.4 adds a second retriever (BM25/hybrid), enabling a
  **multi-method pool** and a trustworthy coverage number. Relevance labels are
  reusable, so nothing is lost by waiting.

### LLM-as-judge: Claude Opus (eval tooling only)

Faithfulness is judged by `claude-opus-4-8` against the retrieved sources. The
RAG generator remains the local Qwen — using an API model to *evaluate* is not
the same as using it to *answer*. Opus reliably caught subtle mis-attribution
(e.g. "[2] does not actually say that").

### Metrics implemented in-repo (no RAGAS)

- **Retrieval:** recall@k, MRR, nDCG@k — short, pure functions, unit-tested.
- **Generation:** faithfulness (fraction of claims supported + a strict
  all-or-nothing per-answer flag). Answer relevance / context precision are
  candidates for a later tag.

## Results (synthetic set)

### Retrieval (n=150 known-item)

| k | recall@k | nDCG@k |
|---|---|---|
| 1 | 0.70 | 0.70 |
| 3 | 0.85 | 0.79 |
| 5 | **0.91** | 0.81 |
| 10 | 0.93 | 0.82 |

**MRR = 0.78.** The source abstract is in the top-5 for 91% of questions,
usually rank 1–2.

**k-sweep → k=5 justified.** Recall gains flatten after k=5 (`@3→@5` = +5pts,
`@5→@10` = only +2pts). k=5 captures almost all findable relevant docs; k=10
barely helps recall while adding noisier context that can hurt faithfulness.

### Generation faithfulness (n=30 known-item, k=5)

- **Faithful rate = 0.80** (24/30 answers fully grounded).
- **Mean faithfulness score = 0.90.**
- Mean > rate ⇒ failures are **partial** (score ~0.5–0.85), not wholesale
  hallucination — most of each answer is grounded, with 1–2 bad claims.

**Characterised failure mode: citation misattribution.** All 6 failures across
30 queries are the same kind: the core finding is correct, but the answer
attributes a specific stat/claim to the wrong source or overstates what a source
shows (never fabrication-from-nothing). This quantifies the anecdotal
knee-extension failure from v0.2 and points the v0.4/v0.5 fix at **citation
precision**, not generic hallucination reduction.

## Known issues / debt

- **Synthetic numbers are optimistic** — questions are phrased from the source
  abstract (easier than real queries). The gold set (v0.4) will be lower/realer.
- **Self-pooling bias** — see gold-set deferral above; gold recall will need a
  multi-method pool to measure coverage rather than just ranking.
- **n=30 for faithfulness** — modest sample; wide-ish error bars. Cheap to scale.
- **Only faithfulness measured** for generation; answer-relevance deferred.
- **faithful ≠ correct** — faithfulness judges grounding in the *retrieved*
  context, not factual correctness or whether retrieval fetched the right docs.
